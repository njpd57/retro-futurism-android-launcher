# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

A retro-futurist Android home screen: a **CRT terminal from a spaceship**, in the spirit of the computers in *Alien* and *Alien: Isolation* (phosphor text, scanlines, inverse-video windows, a ship's computer called MOTHER). It is a web project that runs as the home screen of [Bridge Launcher](https://github.com/bridgelauncher/launcher), an Android app that shows a WebView and exposes Android features to it through `window.Bridge`. There is no native Android code here (the Kotlin lives in our Bridge fork, see below).

It started from Bridge's `api-tester` example, but it is now its own product: a three-tab launcher (PANEL / APPS / MOTHER) with a window-based dashboard, notifications, media, agenda, weather, an AI chat and two minigames.

Stack: Vue 3 (`<script setup>`), TypeScript, Pinia setup stores, VueUse, SCSS, Vite 4 and Vitest. **User-facing text is in Spanish** (`index.html` is `lang="es"`, and so is the README); code and comments are in English.

## Art direction

Every change should feel like it belongs to the same machine. When in doubt, ask: *would this appear on a 1979 starship terminal?*

- **Phosphor, not colors.** The whole UI is one color on near-black: `--ph` (text), `--ph-dim` (secondary), `--ph-bg` (background), `--ph-glow` (bloom). Palettes: amber (default), green, white P4, blue, red; they are blocks in `src/assets/styles/crt.scss`. Never hardcode a hex color in a component; use the variables so every palette works. Hierarchy comes from brightness (`--ph` vs `--ph-dim`), inverse video and borders, not from hues.
- **Light is the effect.** Text and boxes glow through the `glow` / `box-glow` mixins, scaled by `--bloom`. Active or selected things are **inverse video** (`@include inverse`: dark text on a lit block), also for `:active` feedback on anything tappable.
- **The screen is a tube.** `CrtScreen` draws the overlay: scanlines, vignette, flicker, a slow sweep band and optional curvature. All of it is user-toggleable and is turned off or frozen under `prefers-reduced-motion`. Curvature is CSS only (rounded corners and inner shadow) so touch targets are never displaced.
- **Type and glyphs.** One font, VT323, large (22px base). Interface labels are in **UPPERCASE Spanish, terse and technical** (`SIN ACCESO AL CALENDARIO`, `[CONCEDER]`, `PUERTAS ▓▓░`), as a ship's computer would say them. Use box-drawing and block characters (`▓░█▁▂▃`, `◉`, `»`, `[ ]`/`[X]`) for bars, sparklines, toggles and radar instead of icons or images. Buttons that act are written `[ASÍ]`.
- **Windows, not cards.** Content lives in `TuiWindow`: a bordered frame with an inverse title bar and a decorative text scrollbar. Menus are windows too (`TermMenu`). No rounded corners, shadows or gradients on components, except the deliberate CRT ones.
- **Motion is mechanical.** Blinking cursors, `steps()` blinks, sweeping lines, data chirps; no easing-heavy or springy UI animation. Canvases and timers must stop on `beforePause` (see `ScopeWidget`).
- **Sound is synthesized and off by default.** Key clicks, square-wave beeps and a low terminal hum with random data chirps, all from Web Audio (`src/audio/`). Never add audio files, and never play sound unless the user enabled it (alarms and game events the user started are the exception).
- **Tone of voice.** MOTHER answers in uppercase, ship-computer style. The Nostromo text adventure and the motion-tracker game are the in-world easter eggs; new content should keep that fiction rather than add generic UI.
- **Restraint.** The aesthetic works because it is sparse: one color, few glyphs, lots of black. Prefer removing decoration to adding it, and keep text legible (contrast between `--ph` and `--ph-bg` must hold in every palette).

## Commands

```bash
npm run dev          # Vite dev server; a BridgeMock stands in for window.Bridge (see below)
npm run build        # type-check (vue-tsc) + vite build -> dist/
npm run type-check   # vue-tsc only
npm run deploy       # build + adb push dist/ to /sdcard/projects/crt-launcher (override with REMOTE_DIR)
npm run test:unit    # vitest in watch mode (jsdom)
npx vitest run --dir src   # all tests once; --dir keeps out the git worktrees under .claude/
```

Tests live in `src/**/__tests__/` (pure logic only: utils, mother, games; excluded from `tsconfig.app.json`, included by `tsconfig.vitest.json`). DOM, canvas, gestures and sound are checked by hand in the dev server and on the device.

To run on a device, point Bridge's "project dir" setting at a folder containing the contents of `dist/`. The Vite build uses stable, unhashed asset names (`assets/index.js`), so copying a new `dist/` over the old one is enough. Don't use adb on the phone without asking; the user does device testing.

Keep `.claude/` (other agents' worktrees) out of commits.

## Bridge runtime

- `Bridge` is a global that only exists inside Bridge. In development, `src/mock/injectBridgeMockInDev.ts` installs `ForkBridgeMock` (a `BridgeMock` from `@bridgelauncher/api-mock` plus fake fork data), which reads its app list and icons from `public/mock/`; calls such as `requestLaunchApp` show an `alert`. Types come from `@bridgelauncher/api` (v0.1.0, the latest). `main.ts` also registers `Bridge` as a Vue global property (typed in `src/BridgeVueGlobalProperty.ts`), so templates can call `Bridge.*` directly.
- **There is a single `window.onBridgeEvent` handler, and `useBridgeEventStore` owns it.** Everything else subscribes with `bridgeEvents.addEventListener(...)`. Never assign `window.onBridgeEvent` anywhere else.
- **Stores follow one pattern:** read the initial value with a `Bridge.get*()` call when the store is created, then update it from the matching `*Changed` event (and re-read on `afterResume` if the permission can change outside Bridge). `useTogglesStore` exposes each setting as a writable `computed` whose setter calls `Bridge.requestSet*()`; the value only changes once Bridge sends the event back.
- **Target platform is our Bridge fork** ([njpd57/bridge-launcher](https://github.com/njpd57/bridge-launcher), checked out at `~/Proyects/bridge-launcher`), not stock Bridge. The fork adds methods, events and fixes on top of the stock API; `BRIDGE_LAUNCHER_GUIDE.md` is the reference for both (stock API in section 4, fork API in section 5, how to extend the fork in section 11). Read it before building a feature on `Bridge.*`.
- **The fork's methods are not in `@bridgelauncher/api` (v0.1.0, the latest).** They are declared by module augmentation in `src/types/bridge-fork.d.ts` (window insets fix flag, battery, connectivity, notifications, media session, calendar, next alarm, `requestOpenUrl`, contacts, app usage, app shortcuts and `getStorageStats`, with their events), faked by `ForkBridgeMock` in `src/mock/injectBridgeMockInDev.ts`, and called behind `bridgeHas()` (`src/utils/bridgeHas.ts`) with a web fallback (`useSystemStatusStore`). When you add a fork method, keep the three in sync with the Kotlin name, and add it to `DIAGNOSTIC_METHODS` in `SettingsPanel`.
- `getStorageStats` was added to the fork's `JSToBridgeAPI.kt` but has not been compiled or installed yet (no Android SDK on the dev machine); until the fork is rebuilt, the STORAGE widget shows "NO DISPONIBLE".
- **Calling a method the installed Bridge doesn't have throws**, and when that happens while a store is being created, the whole launcher fails to load. Check with `typeof Bridge.someMethod === 'function'` (`bridgeHas`) before using a method that hasn't been tried on the device. The fork-based stores and `useSystemStatusStore` are guarded; the older stores (`useTogglesStore`, `useWindowInsetsStore`) still call their getters unguarded.
- **Window insets:** the fork fixes the stock bugs (top and left swapped, window-insets events as `{ name: 'ImeWindowInsetsChanged', insets }` instead of `{ name: 'imeWindowInsetsChanged', newValue }`), and `Bridge.getWindowInsetsSwapFixed()` is present only on the fork. `useWindowInsetsStore` doesn't yet accept the stock event format or unswap, so it only works as intended on the fork. Also, `statusBars` insets are 0 while the status bar is hidden; the size it would have is in the `IgnoringVisibility` variants.
- **The API can't** receive back-button events (Bridge forwards back to the WebView history, so `history.pushState` works as a workaround), embed native app widgets, or open intents beyond the ones the guide lists (launch by package, the supported URL schemes, app shortcuts). Notifications can be read only through the fork. App shortcuts only work when Bridge is the default launcher. Don't design features that need anything else.

## Layout

- `src/main.ts`: loads the global styles, injects the mock, creates the app with Pinia.
- `src/App.vue`: composes the screen (optional `StatusBar`, `TopBar` with the PANEL / APPS / MOTHER tabs, the active tab's content, prompt, `SoftKeys`) inside `CrtScreen`. It handles overlays (settings, app menu with the app's launcher shortcuts, notifications) with `history.pushState`/`popstate` for back and `newIntent` for home, and forces an opaque page with no overscroll glow (restoring Bridge's previous values on teardown). With `settings.ownStatusBar` it hides the system status bar (`useOwnStatusBar`) and draws its own.
- `src/widgets/registry.ts`: the only list of dashboard widgets (`kind` -> title, component, grid span, props). The dashboard layout (`settings.layouts`: up to four panels P1..P4, each an array of `{ id, kind, minimized }`; `settings.dashboard` is a writable computed over the visible panel. Widget ids are unique across all panels because they key the widget's stored state) references kinds from here; edit it with the pure functions in `src/utils/dashboardLayout.ts`. To add a widget: write the component in `src/components/widgets/` (it receives its instance `id` as a prop and renders only its content; `TuiWindow` is the frame; per-instance data goes in `useLocalStorage('widget.<kind>.<id>')`) and add one line to the registry.
- `src/components/`: `TuiWindow` (retro window: inverse title bar with minimize / move / close, scroll indicator; also the frame of every menu through `TermMenu`), `Dashboard` (the PANEL tab: a grid of windows, with an edit mode), `StatusBar`, `NotificationWindow`, `MotherTerminal` / `MotherSettings` (the MOTHER chat), `SoftKeys` (bottom key row), `CrtScreen` (phosphor palette, `--bloom`, CRT overlay, delegated UI sounds), `TopBar`, `AppList` / `AppRow` / `FolderBox` (long press via `src/composables/useLongPress.ts`; optional monochrome icon), `PromptBar`, `MenuItem`, `SettingsPanel`.
- `src/components/widgets/`: `ClockWidget`, `PowerWidget`, `LinkWidget`, `AppShortlistWidget`, `ScopeWidget` (canvas, paused on `beforePause`), `LogWidget`, `NotesWidget`, `AgendaWidget`, `MediaWidget`, `AlarmWeatherWidget`, `MotherWidget`, `RadarWidget` (ASCII radar, notifications as blips), `StorageWidget`, `ContactsWidget` (starred; a tap opens the dialer, never calls directly), `ScreenTimeWidget`, `TimerWidget`, `TrackerWidget` (motion-tracker minigame), `RerouteWidget` (power-routing minigame), `NostromoWidget` (text adventure), `ProtocolWidget` (daily checklist), `CountdownWidget`, `WorldClockWidget`, `MoonWidget`, `ForecastWidget` (7 days, reuses `useWeatherStore`), `TelemetryWidget` (latency to a host) and `CompassWidget` (`deviceorientationabsolute`), `ImageWidget` (the imported pictures with the CRT filter; a tap opens the viewer). `TimerWidget` also has a stopwatch mode. Looping widgets use `usePausableInterval` (stops on `beforePause`).
- **Image viewer:** `ImageViewer` (overlay opened by `> imagenes` or the `[IMÁGENES]` button, state in `useImagesStore`) lists pictures the user imported through `<input type=file>`; Bridge has no gallery API. `utils/imageDb.ts` keeps them in IndexedDB, shrunk to 1280 px JPEG (not in the backup). `CrtImage` draws them on a canvas with `utils/crtFilter.ts` (pure, tested: duotone between `--ph-bg` and `--ph` read from CSS, CRT color; no scanlines of its own, `CrtScreen` already draws them); `settings.imageFilter` picks the mode. The `[PREGUNTAR A MOTHER]` row in `ExtraResults` sends the typed text to the chat (`askMother` in `App.vue`).
- `src/games/`: pure, tested logic of the minigames (`tracker.ts` and `reroute.ts` with injected RNG, `nostromo.ts` with `reduce(state, input)`).
- **Command assist:** `utils/commandRegistry.ts` (pure) lists the commands of the `>` console and of the MOTHER chat (`/temp`, `/nota`, `/tema`, `/abrir`, `/ordenar`, `/sesiones`, `/nueva`, `/borrar`, `/ayuda`; `ESTADO` and `INFORME` need no prefix) and builds the suggestions, the grey ghost text and what TAB fills in; `AssistedInput` is the UI (chips, ghost, `[TAB]` button, Tab key) used by `PromptBar` and `MotherTerminal`. `mother/slash.ts` parses the `/commands`; they run on the phone with no API.
- **MOTHER organizes apps** (`mother/organizer.ts` pure, `useOrganizerStore`, `MotherOrganizer`): only the numbered NAMES of the visible apps are sent (never package names or usage), the answer is validated (`parsePlan`), shown as a preview and applied only with `[APLICAR]`; `[DESHACER]` restores the previous folders and favorites. Entry points: `> mother <orden>`, the `[MOTHER]` button in the app list, `/ordenar` and the `organizar_apps` tool.
- **Permissions and speech:** `AJUSTES › PERMISOS` (`PermissionsMenu`) lists every permission and capability with its state and `[CONCEDER]`. `useSpeechStore` speaks through the WebView's `speechSynthesis` when it has a Spanish voice, otherwise through the fork's Android text-to-speech (`requestSpeak`, uncompiled Kotlin: the user must rebuild the fork). Speech needs no runtime permission, only an engine and a voice. Weather requests go through `fetchJsonViaProxy` (falls back to `Bridge.getProxyURL`).
- `src/audio/`: Web Audio synthesis, no sound files (`context.ts` shared AudioContext and volume, `sfx.ts` clicks and beeps, `ambient.ts` terminal hum). `useSoundStore` gates them by settings and pauses on `beforePause`; `CrtScreen` plays the select/key sounds with one delegated listener (add the `pressable` class to make an element click).
- `src/mother/`: pure pieces of the chat, all tested: persona prompt, SSE parser (text, token usage and streamed tool calls), message building, key masking, error texts, `local.ts` (`ESTADO` / `INFORME` / `ORDEN ESPECIAL 937` answered offline, plus the `ShipSnapshot` and `contextBlock` sent as context), `context.ts`, `sessions.ts`, `voice.ts` and `actions.ts` (tool definitions and validation: the model's proposals are never run without the user's `[EJECUTAR]`). **The ship context is on by default** (user's decision) and is shown in `MotherSettings`; keep it visible there if you change what is sent. The OpenAI API key is typed by the user in the settings and kept only in the phone's localStorage; never put a key in the repo, an `.env` or the build (Vite would inline it into `dist/`).
- `src/stores/`: `useAppsStore` (installed apps as a `Map` keyed by package name, fetched from `Bridge.getAppsURL()`, kept in sync with `appInstalled` / `appChanged` / `appRemoved`; each app gets a `labelSimplified` for searching), `useWindowInsetsStore`, `useTogglesStore`, `useBridgeEventStore`, `useSettingsStore` (phosphor, bloom, CRT effects, sound, icons, hidden apps, favorites, active tab, dashboard; persisted in localStorage), `useLaunchStore` (the only place that calls `requestLaunchApp`; keeps recents), `useSystemStatusStore` (battery, connectivity, storage), `useLogStore` (ring buffer for the log widget), `useNotificationsStore`, `useMediaStore`, `useCalendarStore`, `useAlarmStore`, `useWeatherStore` (Open-Meteo, no key; city and last forecast cached), `useMotherStore` (chat with streaming), `useContactsStore` (starred contacts), `useUsageStore` (app usage since midnight), `useSoundStore`, `useIdleStore` (idle clock). Every store that uses a fork method guards it with `bridgeHas()` and degrades to an empty state.
- `src/composables/`: `useCommandConsole` (the `>` prompt; parsing is `utils/commands.ts`), `useSwipe` (touch events, passive; ignores `input, textarea, canvas, [data-no-swipe]`), `useShipSnapshot`, `useDashboardActions` (save a note, start a timer from the console or MOTHER), `usePausableInterval`, `useAppShortcuts`, `useLongPress`.
- `src/utils/`: `px()` for inline styles, `simplifyString()` (lowercase, accents stripped, ASCII letters and digits only; it drops spaces), `searchApps()` (ranked search, pure and tested), `appTypeLabel()`, `tui.ts` (bars, sparklines, byte and time formatting), `recents.ts`, `bridgeHas.ts`, `dashboardLayout.ts`, `notifications.ts`, `notes.ts`, `agenda.ts`, `media.ts`, `weather.ts`, `radar.ts`, `contacts.ts`, `usage.ts`, `timer.ts` (with the stopwatch), `commands.ts`, `swipe.ts`, `backup.ts`, `nightShift.ts`, `idle.ts`, `boot.ts`, `haptics.ts`, `folders.ts`, `alphaIndex.ts`, `newApps.ts`, `webSearch.ts`, `protocol.ts`, `countdown.ts`, `worldClock.ts`, `moon.ts`, `telemetry.ts`, `compass.ts`, `day.ts` (all pure and tested except `haptics`' `tick`).
- `src/assets/styles/`: `page.scss` (html/body/#app full size), `base.scss` (the `.launcher-root` look: VT323 in the phosphor color with bloom, no tap highlight, no text selection), `crt.scss` (the phosphor palettes as CSS variables; add a color by adding a block and an entry in `PHOSPHORS` in `useSettingsStore`). `shared/vars.scss` (durations, easing) and `shared/mixins.scss` (`glow`, `box-glow`, `inverse`) are injected by Vite into every SCSS block, so they're available without importing.
- **APPS folders as boxes** (`settings.folderBoxes`, default on): the APPS root is a 2-column grid of `FolderBox` (system boxes `FAVORITAS` / `RECIENTES` / `NUEVAS` are filters, then the user's folders) above the apps that are in no folder; opening a box lists only its apps. The pure model is `utils/appGroups.ts` (`buildBoxes`, `looseApps`, tested); the open box lives in `useAppsViewStore` (not persisted; closed on leaving the tab and on Home). Search is always flat. Off = the old inline accordion. `App.vue` keeps **two history layers** (overlay and open box); closing one from the UI calls `history.back()` and `expectedPops` makes that popstate skip the handler, so keep both flags in sync if you add a layer.
- `BRIDGE_LAUNCHER_GUIDE.md`: technical guide to the stock and fork APIs, event hub, insets, launcher architecture and pitfalls. `FEATURES.md`: ideas for later. `README.md` (Spanish): user-facing description and permissions.
- `@/` is an alias for `src/`.

## Gotchas

- **`useLocalStorage(key, null)` corrupts objects.** VueUse picks its "any" serializer for a `null` default, which writes `String(value)`: an object is saved as `"[object Object]"` and comes back as a string after a reload (this blanked the weather widgets). For nullable objects or numbers pass `{ serializer: nullableJson(isX) }` from `utils/storage.ts`, which stores JSON and reads anything invalid as `null`.
- **Text fields:** use `TermInput` (not `v-model` on an `<input>`). `v-model` ignores `input` events while an Android keyboard composes a word, so the value is stale until a space or on Enter; `TermInput` reads the element's own value and sets `enterkeyhint` so Enter doesn't jump the focus to the next field (it used to land in the prompt at the bottom).
- **A widget that throws** shows `FALLO DE VENTANA` (`WidgetBoundary`, wrapped around each widget by `Dashboard`) and logs it, instead of rendering blank. Read Bridge JSON getters with `readJson()` (`utils/safeJson.ts`).
- **Backup** (`utils/backup.ts`) only carries localStorage keys starting with `settings.` or `widget.`. A new persisted setting under another prefix will not be backed up; `mother.*` and `apps.firstSeen` are deliberately left out.
- **App install dates** are not in the Bridge API: `useAppsStore.firstSeen` records when the launcher first saw each package (the first scan marks everything as old).
- **Gestures** use touch events, not pointer events (pointer events get cancelled once the browser starts scrolling). Put `data-no-swipe` on any new element that handles its own horizontal drags.
- **Scrolling:** the dashboard is the scroll container; a window body (`TuiWindow .body`) scrolls only when it exceeds 45vh. Don't put `overscroll-behavior: none` or `touch-action: none` on anything inside a widget, or a drag that starts there won't scroll the dashboard. Handle taps with `click`, not `pointerdown`, on widget surfaces.
- **Audio** needs a user gesture before it starts (`useSoundStore` unlocks on the first pointer or key event) and is suspended on `beforePause`.
- **Reduced motion:** any new looping animation must respect `prefers-reduced-motion`.
