# Architecture and layout

Moved from CLAUDE.md. Where things live: dashboard and widgets, settings, stores, utils, protocols, MOTHER, APPS. For the ship see `SHIP_PANEL.md`, for games `GAMES_ENGINE.md`.

- `src/main.ts`: loads the global styles, injects the mock, creates the app with Pinia.
- `src/App.vue`: composes the screen (optional `BridgeConsole`, `TopBar` with the PANEL / APPS / MOTHER tabs, the active tab's content, prompt, `SoftKeys`) inside `CrtScreen`. It handles overlays (settings, app menu with the app's launcher shortcuts, notifications) with `history.pushState`/`popstate` for back and `newIntent` for home, and forces an opaque page with no overscroll glow (restoring Bridge's previous values on teardown). With `settings.ownStatusBar` it hides the system status bar (`useOwnStatusBar`) and draws its own, the bridge console (below).
- `src/widgets/registry.ts`: the only list of dashboard widgets (`kind` -> title, component, `sizes`, props). The dashboard layout (`settings.layouts`: up to eight panels (decks) with a stable `ids[]` and `names[]` (default PUENTE / SENSORES / BITÁCORA / RECREO; old sets read as P1..PN), each an array of `{ id, kind, minimized }`; protocol `panel` effects point at a deck by `deck` id with `index` as fallback; in edit mode a title-bar hold drags a window onto another window (`moveWidgetTo`, insert before/after) or onto a deck tab (`moveWidgetToPanel`), `⧉` duplicates and `[DESHACER]` undoes (`pushHistory`); tapping the active tab (or `▦`) opens `DeckPlan`, the ship's plan with every deck as a compartment holding a miniature of its grid; **living windows** (`settings.liveWidgets`, `utils/attention.ts` pure, `useAttentionStore`): radar follows the MSG lamp, alarm the ALM lamp and power the battery; such a window grows one size (`grownSize`, at most `MAX_GROWN` at once, a notice for `NOTICE_MS`, an urgent one while it lasts) and its frame blinks in steps when urgent; `Dashboard` applies the change only while no finger is down and never while editing, and the growth is never saved; `[PLANTILLAS]` (edit mode) replaces all decks with a `LAYOUT_TEMPLATES` set (`templateSet`, TRABAJO / NOCHE / VIAJE / FÁBRICA) as one undoable edit, and a protocol that switches deck logs `PRT: CUBIERTA <name>`; `settings.dashboard` is a writable computed over the visible panel. Widget ids are unique across all panels because they key the widget's stored state) references kinds from here; edit it with the pure functions in `src/utils/dashboardLayout.ts`. **Sizes:** a window is `s` 1x1, `w` 2x1, `t` 1x2 or `l` 2x2 cells (`WidgetSize`, `SIZE_CELLS`); a widget lists the sizes it looks good at in `sizes` (the first is the default) and each `DashboardItem` may carry its own `size` (`sizeOf`, `cycleSize`; absent = the default, so older saved layouts still load). `Dashboard` is a 2-column grid with fixed-height rows (`grid-auto-rows`), `TuiWindow` with `fill` is as tall as its cell and its body is a size container, so a widget must fill `height: 100%` and adapt with `@container` (hide secondary lines in a 1x1). The `◢` button in edit mode cycles the size. A fresh install starts from `DEFAULT_PANELS` (four themed panels, `defaultLayoutSet()`); `[RESTABLECER PANELES]` in the settings loads them again. To add a widget: write the component in `src/components/widgets/` (it receives its instance `id` as a prop and renders only its content; `TuiWindow` is the frame; per-instance data goes in `useLocalStorage('widget.<kind>.<id>')`) and add one line to the registry with its `category`, a one-line `description` and a `preview` (2-3 static glyph lines); the add-window menu is `WidgetCatalog` (category tabs, search and cards built with `utils/widgetCatalog.ts`, pure and tested), and a test fails if a widget lacks them.
- `src/components/`: `TuiWindow` (retro window: inverse title bar with minimize / move / close, scroll indicator; also the frame of every menu through `TermMenu`), `Dashboard` (the PANEL tab: a grid of windows, with an edit mode), `NotificationWindow`, `MotherTerminal` / `MotherSettings` (the MOTHER chat), `SoftKeys` (bottom key row), `CrtScreen` (phosphor palette, `--bloom`, CRT overlay, delegated UI sounds), `TopBar`, `AppList` / `AppRow` / `FolderBox` (long press via `src/composables/useLongPress.ts`; optional monochrome icon), `PromptBar`, `MenuItem`, `SettingsPanel` (see below).
- **Settings page** (`SettingsPanel`): a full-screen page, not a `TermMenu`. Its sections and rows are data in `utils/settingsSchema.ts` (pure, tested: `SETTINGS_SECTIONS`, `visibleRows`, `summary`; each row has a `hint` shown in the footer when touched); the page only paints them with `MenuItem` toggles, `settings/TermSlider` (GaugeBar + `[-]`/`[+]`, touch drag, `valueAt` in `utils/gauge.ts`) and `settings/TermChoice` (unfolds every option). To add a setting, add a row to the schema; keep the store key. Sections with `preview` show `[MANTÉN: VER TUBO]`, which fades the page out while held. The open section and submenu live in `useSettingsViewStore`; back steps out of them first (`App.vue` `onPopState` calls `settingsView.back()` and pushes the overlay entry again).
- `src/components/widgets/`: `ClockWidget`, `PowerWidget`, `LinkWidget`, `AppShortlistWidget`, `ScopeWidget` (canvas, paused on `beforePause`), `LogWidget`, `NotesWidget`, `AgendaWidget`, `MediaWidget`, `AlarmWeatherWidget`, `MotherWidget`, `RadarWidget` (SVG radar with a sweep and a fading trail, notifications as blips; one blip per *app* (`radarContacts`, heavier with 3+ signals); a tap on a blip (an SVG element, so the curvature correction of `click` applies) scans it and lists that app's notifications, each with open / dismiss / its buttons), `StorageWidget`, `ContactsWidget` (starred; a tap opens the dialer, never calls directly), `ScreenTimeWidget`, `TimerWidget`, `TrackerWidget` (motion-tracker minigame), `RerouteWidget` (power-routing minigame), `NostromoWidget` (text adventure), `ProtocolWidget` (daily checklist), `CountdownWidget`, `WorldClockWidget`, `MoonWidget` (SVG disc, lit part from `moonPath`), `ForecastWidget` (7 days, reuses `useWeatherStore`), `TelemetryWidget` (latency to a host), `SentinelWidget` (CENTINELA: up/down of the user's sites, see `useSentinelStore`) and `CompassWidget` (SVG rose that turns, `deviceorientationabsolute`), `ImageWidget` (the imported pictures with the CRT filter; a tap opens the viewer). `TimerWidget` also has a stopwatch mode. Looping widgets use `usePausableInterval` (stops on `beforePause`).
- **Image viewer:** `ImageViewer` (overlay opened by `> imagenes` or the `[IMÁGENES]` button, state in `useImagesStore`) lists pictures the user imported through `<input type=file>`; Bridge has no gallery API. `utils/imageDb.ts` keeps them in IndexedDB, shrunk to 1280 px JPEG (not in the backup). `CrtImage` draws them on a canvas with `utils/crtFilter.ts` (pure, tested: duotone between `--ph-bg` and `--ph` read from CSS, CRT color; no scanlines of its own, `CrtScreen` already draws them); `settings.imageFilter` picks the mode. The `[PREGUNTAR A MOTHER]` row in `ExtraResults` sends the typed text to the chat (`askMother` in `App.vue`).
- **Command assist:** `utils/commandRegistry.ts` (pure) lists the commands of the `>` console and of the MOTHER chat (`/temp`, `/nota`, `/tema`, `/abrir`, `/ordenar`, `/sesiones`, `/nueva`, `/borrar`, `/ayuda`; `ESTADO` and `INFORME` need no prefix) and builds the suggestions, the grey ghost text and what TAB fills in; `AssistedInput` is the UI (chips, ghost, `[TAB]` button, Tab key) used by `PromptBar` and `MotherTerminal`. In the APPS prompt the `>` is optional: `parseCommand` also takes a known command word without it (not the one-letter aliases), and such a command only takes Enter when it acts, otherwise Enter opens the first app. `CommandList` shows every command while the prompt is focused and empty (and for `ayuda`), and the ones matching the typed word (`matchCommands`) above the apps. `mother/slash.ts` parses the `/commands`; they run on the phone with no API.
- **MOTHER organizes apps** (`mother/organizer.ts` pure, `useOrganizerStore`, `MotherOrganizer`): only the numbered NAMES of the visible apps are sent (never package names or usage), the answer is validated (`parsePlan`), shown as a preview and applied only with `[APLICAR]`; `[DESHACER]` restores the previous folders and favorites. Entry points: `> mother <orden>`, the `[MOTHER]` button in the app list, `/ordenar` and the `organizar_apps` tool.
- **Permissions and speech:** `AJUSTES › PERMISOS` (`PermissionsMenu`) lists every permission and capability with its state and `[CONCEDER]`. `useQuickSettingsStore` holds the phone's quick settings the ship's controls work (flashlight, brightness, ringer, media volume, night mode, Wi-Fi / Bluetooth / location read-only) and the two permissions they need, shown as rows `AJUSTES DEL SISTEMA` and `NO MOLESTAR`. `useSpeechStore` speaks through the WebView's `speechSynthesis` when it has a Spanish voice, otherwise through the fork's Android text-to-speech (`requestSpeak`, compiled into the fork and tested on the device). Speech needs no runtime permission, only an engine and a voice. Weather requests go through `fetchJsonViaProxy` (falls back to `Bridge.getProxyURL`).
- `src/audio/`: Web Audio synthesis, no sound files (`context.ts` shared AudioContext and volume, `sfx.ts` clicks and beeps, `ambient.ts` terminal hum). `useSoundStore` gates them by settings and pauses on `beforePause`; `CrtScreen` plays the select/key sounds with one delegated listener (add the `pressable` class to make an element click).
- `src/mother/`: pure pieces of the chat, all tested: persona prompt, SSE parser (text, token usage and streamed tool calls), message building, key masking, error texts, `local.ts` (`ESTADO` / `INFORME` / `ORDEN ESPECIAL 937` answered offline, plus the `ShipSnapshot` and `contextBlock` sent as context), `context.ts`, `sessions.ts`, `voice.ts` and `actions.ts` (tool definitions and validation: the model's proposals are never run without the user's `[EJECUTAR]`). **The ship context is on by default** (user's decision) and is shown in `MotherSettings`; keep it visible there if you change what is sent. The OpenAI API key is typed by the user in the settings and kept only in the phone's localStorage; never put a key in the repo, an `.env` or the build (Vite would inline it into `dist/`).
- `src/stores/`: `useAppsStore` (installed apps as a `Map` keyed by package name, fetched from `Bridge.getAppsURL()`, kept in sync with `appInstalled` / `appChanged` / `appRemoved`; each app gets a `labelSimplified` for searching), `useWindowInsetsStore`, `useTogglesStore`, `useBridgeEventStore`, `useSettingsStore` (phosphor, bloom, CRT effects, sound, icons, hidden apps, favorites, active tab, dashboard; persisted in localStorage), `useLaunchStore` (the only place that calls `requestLaunchApp`; keeps recents), `useSystemStatusStore` (battery, connectivity, storage), `useLogStore` (ring buffer for the log widget), `useNotificationsStore`, `useMediaStore`, `useCalendarStore`, `useAlarmStore`, `useWeatherStore` (Open-Meteo, no key; city and last forecast cached), `useMotherStore` (chat with streaming), `useContactsStore` (starred contacts), `useUsageStore` (app usage since midnight), `useSoundStore`, `useIdleStore` (idle clock), `useTubeStore` (degauss, tube power), `useShipClockStore`, `useBridgeConsoleStore`, `useProtocolsStore`, `useEffectiveSettings`, `useAlertsStore`, `useSentinelStore` (probes `settings.sentinelSites` every minute through `Bridge.getProxyURL` so HTTP 5xx counts as down, falling back to a no-cors fetch; two failures in a row to go down, paused while offline; `utils/sentinel.ts` pure and tested; feeds the `site` ship alert), `useRemindersStore`, `useQuarantineStore`. Every store that uses a fork method guards it with `bridgeHas()` and degrades to an empty state.
- `src/composables/`: `useCommandConsole` (the `>` prompt; parsing is `utils/commands.ts`), `useSwipe` (touch events, passive; ignores `input, textarea, canvas, [data-no-swipe]`), `useShipSnapshot`, `useReducedMotion` (`prefersReducedMotion()` for one-shot reads, `useReducedMotion()` reactive: use these instead of calling `matchMedia`), `useDashboardActions` (save a note, start a timer from the console or MOTHER), `usePausableInterval`, `useAppShortcuts`, `useLongPress`.
- `src/utils/`: `px()` for inline styles, `simplifyString()` (lowercase, accents stripped, ASCII letters and digits only; it drops spaces), `searchApps()` (ranked search, pure and tested), `appTypeLabel()`, `tui.ts` (bars, sparklines, byte and time formatting), `recents.ts`, `bridgeHas.ts`, `dashboardLayout.ts`, `notifications.ts`, `notes.ts`, `agenda.ts`, `media.ts`, `weather.ts`, `radar.ts`, `contacts.ts`, `usage.ts`, `timer.ts` (with the stopwatch), `commands.ts`, `swipe.ts`, `backup.ts`, `nightShift.ts`, `idle.ts`, `boot.ts`, `haptics.ts` (vibrates through the fork's `requestVibrate`; the WebView has no `navigator.vibrate`), `folders.ts`, `alphaIndex.ts`, `newApps.ts`, `webSearch.ts`, `protocol.ts`, `countdown.ts`, `worldClock.ts`, `moon.ts`, `telemetry.ts`, `compass.ts`, `day.ts`, `curvature.ts` (all pure and tested except `haptics`' `tick`).
- `src/assets/styles/`: `page.scss` (html/body/#app full size), `base.scss` (the `.launcher-root` look: VT323 in the phosphor color with bloom, no tap highlight, no text selection), `crt.scss` (the phosphor palettes as CSS variables; add a color by adding a block and an entry in `PHOSPHORS` in `useSettingsStore`). `shared/vars.scss` (durations, easing) and `shared/mixins.scss` (`glow`, `box-glow`, `inverse`) are injected by Vite into every SCSS block, so they're available without importing.
- **Dragging apps into folders** (`AppList`, only with the folder boxes on screen): `AppRow` uses touch events through `useRowDrag` (hold 450 ms to lift, then drag; releasing without moving opens the long-press menu, so on a finger the menu opens **on release**; the mouse keeps the old long press). The drop target is found with `elementAtPoint` (`utils/pointUnder.ts`, applies the curvature correction) over `[data-drop-box]`; `dropAction`, `autoScrollSpeed` and the thresholds are pure in `utils/dragDrop.ts`. A drag that ended prevents the default of its `touchend`, which `useSwipe` and the click both respect. `[+ NUEVA CARPETA]` opens `AppFolderMenu` for the dropped app.
- **Deck map** (`settings.appsLayout = 'deck'`, only with the folder boxes on): `DeckMap` draws the same boxes as compartments on both sides of a double-line corridor, the system ones renamed by `utils/deckMap.ts` (`roomName`), with a door that opens in `DOOR_FRAMES` before `appsView.open`. Rooms are CSS borders, not box-drawing characters: VT323 is loaded as its latin subset only, so characters like `┌ │ ║` fall back to another font and would not line up (the block glyphs `▓▒░` are fine because they only appear inside one text run). It takes the same drop state as the boxes, so dragging apps works in both.
- **Protocols and alerts** (`src/protocols/`, pure and tested): `rules.ts` is the engine of PROTOCOLOS DE TURNO (`Rule { when: Condition[], then: Effect[] }`, `evaluate`, `overlay`, `normalizeRules`; a rule with no conditions never runs; time ranges may wrap midnight and the morning part counts for the day that started it) and `alerts.ts` (`pendingAlerts`) builds the ship alerts. `useProtocolsStore` (`settings.protocols`) evaluates the rules against `useShipClockStore` (a 30 s clock that stops on `beforePause`) and the battery and connectivity of `useSystemStatusStore`; it logs `PRT:` lines and shows the panel a rule asks for once, when it starts. **Protocols never write the user's settings**: `useEffectiveSettings` (`phosphor`, `bloom`, `night`, `hiddenApps`, `bigClock`) lays the active overlay over them and is what `CrtScreen`, `CrtImage`, the APPS list, `AppShortlistWidget` and `useIdleStore` read; read it, not `settings.phosphor` / `settings.hiddenApps`, wherever the screen's look or the visible apps matter (commands and MOTHER keep using the user's own values). `useAlertsStore` drives `AlertStrip` (dismissed by id and by day in `widget.alerts.dismissed`; the klaxon goes through `sound.play`, so it respects the sound setting). Reminders: `utils/reminders.ts` (`parseReminder`: `18:30 x`, `en 20 min x`, `mañana 9:00 x`), `useRemindersStore` (`widget.reminders`), `> recordar`, `/recordar` and `RemindersWidget`; they only fire while the launcher runs until the fork gets its `AlarmManager` scheduling. UI: `ProtocolsMenu` / `ProtocolEditor` under SETTINGS.
- **Quarantine and the weekly report:** `useQuarantineStore` (`settings.quarantine`: package -> daily budget in minutes, 0 = none) holds the launch waiting at the gate. The gate is in `useLaunchStore.launch()`, the only caller of `requestLaunchApp`, so every route is covered; `launchNow` skips it and is for `QuarantineGate` only. The gate and `QuarantineMenu` are overlays registered in `overlayOpen` and `closeOverlays` in `App.vue`; `menuAction` closes the overlays *before* running its action, because closing cancels a pending gate. Pure logic in `utils/quarantine.ts`. `useUsageStore.loadHistory()` fills `history` (14 days, one `getAppUsageURL` range per day, closed days cached in `widget.weekly.cache`), `utils/weeklyReport.ts` builds the report (`WeeklyReportWidget`, `> semana`); `[COMENTAR]` is the only thing that sends it to the API.
- **MEDIA skin and the pod:** `MediaWidget` keeps its skin per instance (`widget.media.<id>.skin`, `TapeDeck`); at night with an alarm set the idle screen is `StasisPod` instead of `IdleClock` (`settings.hypersleep`, `stasisActive` in `utils/stasis.ts`; the vitals are simulated; `> estasis` shows it at once).
- **APPS folders as boxes** (`settings.folderBoxes`, default on): the APPS root is a 2-column grid of `FolderBox` (system boxes `FAVORITAS` / `RECIENTES` / `NUEVAS` are filters, then the user's folders) above the apps that are in no folder; opening a box lists only its apps. The pure model is `utils/appGroups.ts` (`buildBoxes`, `looseApps`, tested); the open box lives in `useAppsViewStore` (not persisted; closed on leaving the tab and on Home). Search is always flat. Off = the old inline accordion. `App.vue` keeps **two history layers** (overlay and open box); closing one from the UI calls `history.back()` and `expectedPops` makes that popstate skip the handler, so keep both flags in sync if you add a layer. The settings page steps back through its section and submenu inside the overlay layer instead of adding one.
